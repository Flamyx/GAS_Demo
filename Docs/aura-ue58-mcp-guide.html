Project Aura Engine 5.7 → 5.8 Toolchain Native MCP + VibeUE 2026-07-12

Upgrading Aura to UE 5.8 and wiring in the AI toolchain

Six phases, in order: protect the working 5.7 project, move the engine version, turn on Epic's built-in MCP server, connect Claude Code, layer VibeUE on top, and prove the whole chain works. Each phase ends with a checkpoint you can verify before moving on.

EngineAura building and playing on UE 5.8, on its own git branch
MCPEditor serving tools at 127.0.0.1:8000/mcp, Claude Code connected
VibeUEExtended toolsets (Blueprints, UMG, Niagara) on top of native MCP
1

Secure the 5.7 project

Goal: a clean commit on 5.7 you can always return to.

Do this first — your tree is dirty

As of today, UE5.7_dev has ~30 modified source files plus untracked spell classes (FireBolt, ElectrocuteCourse) that have never been committed. An engine upgrade on top of uncommitted work means you can't cleanly separate "upgrade breakage" from "my in-progress changes."

PowerShell — project root
# commit everything working on 5.7, then branch for the upgrade
git add -A
git commit -m "Pre-5.8 checkpoint: working Electrocute beam, debuff params"
git checkout -b UE5.8_dev

Install UE 5.8 from the Epic Games Launcher alongside 5.7 — don't replace it. Keeping both installed lets you open the old branch in the old editor at any time.

One-way door

Assets re-saved in 5.8 cannot be opened by 5.7 again. Git makes this survivable — Content/ is committed, so the branch is your rollback — but it's why the upgrade gets its own branch and why Epic's own guidance is to convert a copy, never your only copy.

Checkpoint

git log shows the checkpoint commit; git branch shows you on UE5.8_dev; the Launcher lists both 5.7 and 5.8.

2

Move the project to 5.8

Goal: Aura compiles, opens, and plays in the 5.8 editor.

  1. Switch the engine association. Right-click Aura.uproject → Switch Unreal Engine version… → 5.8 (this rewrites "EngineAssociation" and regenerates Aura.sln). Editing the field by hand and then Generate Visual Studio project files works identically.
  2. Build before opening the editor. Build the Aura target (Development Editor, Win64) from Visual Studio or Rider. Fixing C++ errors in the IDE beats staring at a failed module-load dialog. No breaking GameplayAbilities changes are documented for 5.8, so expect deprecation warnings rather than hard errors — but 5.8's more aggressive unity-build grouping can surface missing #includes that older builds masked.
  3. Open the editor and let it churn. First launch recompiles shaders and updates asset caches; that's normal and slow once.
  4. Re-save deliberately, not wholesale. Open the maps and core Blueprints you actually use (Dungeon map, BP_AuraHUD, ability BPs) and save as prompted. Skip "Fix Up Redirectors on everything" heroics until the project is proven stable.
Niagara — learned the hard way

Do not blanket-accept "Upgrade to newest version" prompts on Niagara module scripts. Upgrading NS_ElectricBeam's modules recreated Initialize Particle with fresh defaults that silently overwrote every particle position and collapsed the beam. If 5.8 offers module upgrades on the VFX pack assets, decline first, confirm the effect works as-is, and upgrade one module at a time with the preview open.

Smoke test in PIE

  • FireBolt and Meteorite fire, damage, and show floating combat text
  • Electrocute beam reaches the cursor hit location (the fix from this week)
  • Spell menu equips/upgrades; attribute menu spends points
  • A quick 2-player PIE session — the equip/upgrade RPC pairs are the most version-sensitive code you have
Checkpoint

Clean build, editor opens without module errors, smoke test passes. Commit: git commit -m "Aura on UE 5.8".

3

Enable the native MCP server

Goal: the editor serves MCP tools on localhost.

UE 5.8 ships an MCP server inside the editor process — no third-party bridge needed. It's experimental: localhost-only, no authentication, APIs subject to change. Treat it as a dev-workflow tool.

  1. Enable the plugin. Edit → Plugins → search "Unreal MCP" → enable (its dependency Toolset Registry enables automatically) → restart the editor.
  2. Auto-start the server. Edit → Editor Preferences → General → Model Context Protocol → enable Auto Start Server. Default endpoint: http://127.0.0.1:8000/mcp. To start manually instead, use the console:
Editor console ( ` )
ModelContextProtocol.StartServer      # optional port arg, e.g. 8000
  1. Enable toolsets. The server itself exposes nothing — tools come from toolset plugins, each disabled by default. In Edit → Plugins, search "Toolset" and enable at minimum:
    • Editor Toolset — actors, Blueprints, properties, screenshots, PIE control
    • UMG Toolset — widget Blueprint authoring (your spell/attribute menus)
    • Niagara Toolsets — system and emitter authoring
    Or enable All Toolsets and prune later. Restart after changing plugins.
Checkpoint

Output Log shows the MCP server listening on port 8000 after editor start.

4

Connect Claude Code

Goal: /mcp shows the editor's tools, green.

  1. Generate the client config from the editor console:
Editor console ( ` )
ModelContextProtocol.GenerateClientConfig ClaudeCode

This writes .mcp.json to the project root:

.mcp.json (generated)
{
  "mcpServers": {
    "unreal-mcp": {
      "type": "http",
      "url": "http://127.0.0.1:8000/mcp"
    }
  }
}
  1. Start Claude Code from the project root (where .mcp.json lives) with the editor running. The config is auto-discovered; approve the project-scoped server when prompted.
  2. Verify with /mcp — unreal-mcp should be connected with a tool count > 0. Zero tools almost always means no toolsets enabled (Phase 3, step 3).
Commit the config

.mcp.json is project-scoped and safe to commit — it contains only a loopback URL. Anyone opening the project with UE 5.8 + Claude Code gets the connection for free.

Checkpoint

Ask Claude Code: "List the actors in the currently open level." A real actor list back = the loop is closed.

5

Add VibeUE on top

Goal: VibeUE's extended tools appear alongside the native ones.

VibeUE extends the three native systems you just enabled (ToolsetRegistry, ModelContextProtocol, AgentSkill) — which is why native MCP had to come first. Two install routes:

RouteHowPick when
FabGet VibeUE on Fab, add to project via the Epic Games LauncherYou want updates managed for you
GitClone the 5-8 branch into Plugins/ (below)You want source and faster fixes
PowerShell — project root
cd Plugins
git clone -b 5-8 https://github.com/kevinpbuckley/VibeUE.git
cd VibeUE
.\BuildAndLaunchGame.ps1
  1. Enable VibeUE in Edit → Plugins, restart the editor.
  2. Generate its agent instructions from the editor console:
Editor console ( ` )
VibeUE.GenerateAgentConfig ClaudeCode
This writes to CLAUDE.md — and Aura already has one

Aura's CLAUDE.md carries the project's architecture documentation (GAS layering, tag conventions, WidgetController pattern). Before running the command, check whether it appends or overwrites: git diff CLAUDE.md immediately after. If it clobbered the file, restore yours and paste VibeUE's generated section in manually.

Optional: VibeUE's hosted terrain tools need a free API key from vibeue.com — everything else works without it.

Checkpoint

/mcp in Claude Code shows a larger tool count than in Phase 4, including VibeUE tool names.

6

Prove the chain end-to-end

Goal: one AI-driven edit, verified in the editor, then a final commit.

  1. Read test: "List every Blueprint under Content/Blueprints that derives from AuraDamageGameplayAbility and report its damage type tag." Cross-check one answer by hand.
  2. Write test (low stakes): have it create a throwaway test asset — a new folder and a dummy Blueprint — then delete it. Confirms write tools work without touching real content.
  3. Real-workflow test: something you'd actually do — e.g., "Open NS_ElectricBeam and report the Beam Emitter Setup bindings on each enabled emitter." You know the correct answer from this week; a correct report means the Niagara toolset genuinely works.
  4. Commit the toolchain state:
PowerShell — project root
git add -A
git commit -m "UE 5.8: native MCP + toolsets + VibeUE wired to Claude Code"
Done

Aura runs on 5.8; the editor serves MCP; Claude Code drives both native and VibeUE tools; all of it reproducible from the branch.
